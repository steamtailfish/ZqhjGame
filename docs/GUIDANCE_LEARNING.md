# YOPO引导学习适配 v0.2

本页是v0.2历史说明。v0.3已更新为51维、加入任务边界、真实公开观测训练、单文件导出与在线推理；最新可执行命令见[TRAINING_AND_INFERENCE.md](../TRAINING_AND_INFERENCE.md)。下文35维和未接入在线控制等表述是当时状态。

用户在v0.1之后明确要求使用YOPO引导学习。本轮已实现**真正更新网络参数的轨迹代价反传**，并完成一次40步CPU合成数据验证。没有执行比赛数据训练，也没有将这份合成权重装入在线Agent。

## 核心区别

v0.1用手工枚举轨迹和解析成本在线挑选。v0.2离线执行：

```text
合法来源的几何特征 → 网络 → 9组基元偏移 → 可微固定翼轨迹 → 轨迹成本J
                         ↑                  ← dJ/d轨迹 ←
                         └──── 链式反传，更新网络参数
                      └→ 分数头 → SmoothL1(score, -J.detach())
```

训练没有专家动作标签，也不需要PPO奖励回合。总损失为可用轨迹的平均代价加0.1倍分数损失；分数标签断开梯度，防止通过改变轨迹代价迎合打分预测。全部分数参与训练；成本≥100的轨迹不直接训练偏移头，全不可用批次采用有连接的零梯度。共享编码器仍可能被分数损失更新。

论文依据：YOPO的II-B-1，式(15)–(21)，PDF第5页。原论文score=-J，取最大分数；本地YOPO仓库的`YopoTrainer.forward_and_compute_loss`采用正代价标签，是不同符号约定。本实现采用论文的**负代价，argmax选分数**，没有混用二者。对照阅读了本地`loss_function.py`、`safety_loss.py`、`guidance_loss.py`和`yopo_trainer.py`，但未复制或修改YOPO源码。

实现使用PyTorch自动微分沿计算图反传，机制见[PyTorch 2.7官方说明](https://docs.pytorch.org/docs/2.7/notes/autograd.html)。数值差分仅用于检查自动微分是否正确，不把有限差分本身当训练器。

## 本项目的适配

| 项目 | 当前实现 |
| --- | --- |
| 网络输入 | 35维结构化几何特征：本机速度、临时目标、观察圆参数、最多2架通信队友、最多4个公开圆形障碍及有效掩码；所有坐标均为t=0机体系，x右、y前，单位m |
| 网络 | 两层64单元Tanh编码器，18维偏移头、9维分数头；没有深度图或RGB编码器 |
| 锚点与偏移 | 3种转率×3种加速度共9组锚点；Tanh偏移使转率始终≤30度/s、加速度≤5m/s² |
| 可微轨迹 | 4秒预测，0.25秒中点积分；速度饱和到15–40m/s；没有直接移植允许停车的四旋翼五次多项式 |
| 安全代价 | 解析圆形有符号距离和队友预测距离的指数势函数，按时间积分；包含消息年龄与预测余量。不是ESDF查询，也没有深度图生成的障碍地图 |
| 其他代价 | 转率/加速度平滑、临时目标距离、可选观察圆误差 |
| 优化 | Adam，梯度范数截断；分数标签与轨迹计算图分离 |
| 当前数据 | 随机生成的局部几何，未读取赛事地图、路线、目标ID或裁判状态 |

这保留了YOPO引导学习的核心梯度链，但没有复现它的完整传感器/轨迹网络架构。采样安全成本也不能代替连续路径安全校验。当前没有任务矩形成本、深度ESDF或真实动力学辨识；网络尚不具备接管飞行的验收条件。

## 文件与复现

- `learning/guidance.py`：Scene特征合同、网络、可微轨迹和引导学习损失。
- `learning/test_guidance.py`：8项梯度/隔离/约束/优化测试，独立于原28项Agent测试。
- `tools/verify_guidance.py`：测试与有限步数合成优化入口，保存源码哈希、环境、训练及留出指标和权重。
- `requirements-learning.txt`：CPU学习依赖，不增加默认在线Agent依赖。

从SIM_ROOT执行，环境不存在时只需建立一次：

```powershell
python -m venv ZqhjGame/.venv-learning
.\ZqhjGame\.venv-learning\Scripts\python.exe -m pip install -r ZqhjGame/requirements-learning.txt
.\ZqhjGame\.venv-learning\Scripts\python.exe -B -X utf8 ZqhjGame/tools/verify_guidance.py --steps 40
```

本机环境为Python3.13.9、PyTorch2.7.1+cpu。工具只使用Tensor；未安装NumPy，因此PyTorch导入时会提示NumPy桥接不可用，8项测试与训练均不使用该桥接。安装时pip最后的自身版本检查遇到TLS错误，但PyTorch及依赖安装成功，后续导入与运算已实际通过。

`.venv-learning/`独立于`run.cmd`自动选择的`.venv/`，不会改变比赛运行解释器；已加入gitignore。`verify_guidance.py`只能把产物写入项目artifacts下的新目录，拒绝覆盖。默认40步，上限200步，是机制验证工具而非正式训练入口。

## 接下来怎样用于比赛

先把真实公开观测转换为相同机体系特征，补齐数据来源、新鲜度和标定证据；再用独立训练/验证场景训练及比较解析基线。推理时让网络提供候选，由真实公开几何和保守运动模型重新做硬约束检查，全部不可行时回退解析规划器。只有通过这些验收，才将网络接入EntryAgent。

如果后续要实现完整“RGB/深度→YOPO”通路，还需真实深度或经过验证的距离估计、相机标定以及配套训练数据。当前单目RGB/photo不能直接当作深度输入。
