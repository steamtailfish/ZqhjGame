## 运行和工具的具体限制

| 现象 | 原因 / 处理方法 |
| --- | --- |
| `Missing learning environment` | `vision.cmd` 只找本仓库 `.venv-learning`；按 [QUICKSTART.md](QUICKSTART.md)重建 |
| 找不到 `competition` 或官方必需文件 | 项目不在发行包内部，或只有 Git 源码；先准备完整官方环境。部分运行入口支持 `--sim-root`，但隔离测试和导出仍使用父目录，因此整体交接采用标准目录布局 |
| 找不到 `vision.pt` 或 hash mismatch | 缺少冻结资产，或混用了不同目录的 `agent.py` 与权重；按清单同步并核对，不修改哈希绕过检查 |
| 导出时找不到 `competition-guidance-v3.py` | 默认值已修正为当前冻结包；如果旧命令还显式传入历史路径，改为 `--controller artifacts/submission/score-v22/agent.py` 复用冻结包内函数 |
| 隔离检查找不到 `.image` | `check_visual_package.py` 依赖固定受控真车照片，该照片已通过 Git LFS 提供；先确认完整下载，不能因此说包推理失败 |
| 训练找不到原机 D 盘图片 | 审核 JSONL 保存了绝对路径，训练脚本直接使用 `image` 字段；按资产清单生成本机副本并核对图片哈希 |
| 同步 JSONL 后仍无法训练 | 还必须同步它引用的图片；源图和审核记录不是同一个文件。脚本不会自动下载数据 |
| 当前包正常运行却完全不报告 | 先确认 `--enable-reports`：本地 runner 会覆盖包的默认值；再区分“候选不足”和“被门限拒绝” |
| 改了 `src/`，结果/行为却没改变 | `--submission` 运行的是导出副本；重新导出并选择新包，检查 `runner-call.json` 哈希 |
| 输出目录已存在 | 入口防止覆盖旧结果；换新时间戳目录，不删除已有实验来重用名字 |
| 6379 占用、UE 启动失败 | 当前视觉运行使用固定端口；核对是否已有自己/队友的回合运行，检查本次日志，不全局清理进程 |
| 裸 `run.cmd agent --agent zqhj_entry:EntryAgent` 与当前包不同 | 这是较早解析入口，不是已评估的完整视觉协同包；当前用 `vision.cmd run --submission artifacts/submission/capture-v26/agent.py ...` |
| 旧文档写着 YOLO、0 分或其他门限 | 冻结 v22 文档、Word 和 FIRST_SCORE 是基线快照；当前使用 README、HANDOFF 和 COOPERATIVE_CAPTURE |

## 下一轮建议交付

1. **复现可交付**：新队友完成资产同步、哈希检查、依赖检查及冻结包运行；记录新机器差异。
2. **捕获可诊断**：用回合结束后的公开照片、动作及外部判定记录解释双机共同跟踪为何未持续满 20 秒，不能仅凭 `OBSERVE` 日志判断。
3. **改进可验收**：一次只围绕一个主要假设修改，导出新包并保存正式 JSON。以至少一次真实清除为捕获里程碑，兼顾坐标精度和惩罚。
4. **高分可统计**：捕获链路打通后再扩展多 seed 和未见场景验证，报告整体表现，而不是最高单次结果。

v22 原始成绩保持不变；v26 单独保存本轮 18.67 分及原始记录。身份迟滞、重获和后续导航调整均为待验证工作，不属于当前 v26 已实现功能。
